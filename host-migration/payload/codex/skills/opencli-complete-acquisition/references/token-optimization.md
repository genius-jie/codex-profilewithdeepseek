# 能力守恒下的上下文去重与分析复用

## 核心不变量

遵循 [Skill 的能力守恒不变量](../SKILL.md#能力守恒不变量)。本参考只解释如何消除已证实的重复工作，不改变原任务的采集范围和语义分析深度：

1. OpenCLI 原始响应、正文、评论、转录、作者页和失败回执仍完整落盘。
2. `complete/partial/unknown/failed` 判定保持原样；调小 limit、删掉 facet、只留高赞样本不属于优化。
3. 本地解析只做结构切分、计数、去重、哈希和引用定位，不做语义淘汰。
4. 暂未送入模型的 chunk 必须有 `chunk_id`、`content_hash`、`raw_ref` 和明确定位方式，仍算待分析，不因有索引就计作完成。
5. 摘要、索引和 Agent 中间结论是派生视图，原始 capture 才是事实源。
6. 首次所需分析完整执行；只对已完成且仍适用的旧分析复用。业务要求全读时，所有单元都应被新分析或有效旧分析覆盖。

## 推荐流水线

```text
OpenCLI 完整采集
  -> 原始 capture + completeness receipt
  -> 本地结构索引（零 LLM token）
  -> Agent 覆盖扫描（短 digest）
  -> Agent 分块深读（source/facet/chunk）
  -> 证据定位的专题综合
  -> 人工决定与正式下游消费
```

## 六种优化

### 1. 结构索引优先

使用 `markdown_it`、标准 XML/JSON 解析器和现有完整性模块生成标题、段落、评论/剧集/引用数量、作者/时间字段、chunk 边界和原始引用。只折叠已证实的重复载荷；短文本、低赞评论、反例、转述和未知 facet 一律保持可寻址。由“短”“像导航”或“低分”推断内容无价值的过滤不属于本优化。

### 2. 两阶段 Agent 消费

覆盖扫描读取候选 ID、facet 状态、字符数和限制，选择下一批 `source_id/facet_id/chunk_id`。这是排队，不是语义筛除；每批大小按上下文预算确定，不将固定前 N 条当成覆盖范围。所有未处理单元保留待分析引用。结论均带原文定位，综合按原任务要求消费已验证分析、相关上下文和准入事实。

若业务要求每个字符都经过语义阅读，采用分块 Map→Reduce：每个 chunk 都产出可回放分析回执，再合并。这样减少重复上下文，保留完整语义覆盖。

### 3. 复用条件与失效处理

复用需要以下条件同时成立；任意条件未知时，回到正常分析路径：

- **证据一致**：当前对象版本、facet/chunk 内容和必要来源关系一致；ID 只定位对象，内容 hash 才参与版本比较。
- **旧分析真实有效**：review 可读、完整、未撤销，有实际覆盖单元及证据定位；只有文件路径、曾经发送过内容或旧 packet 不构成已审证明。
- **分析任务相容**：问题、规则/提示版本、所需深度、模型能力要求、解析/分块语义和必要时间语境一致或已有兼容依据。原文未变而问题改变时，旧结论不自动复用。
- **依赖仍成立**：父帖、上文、说话者、字幕时间、作者信息等影响理解的依赖已核对；新增或变化证据使相关综合结论重新计算，未受影响的局部分析才继续复用。

增量比较覆盖新增、编辑、删除和影响理解的重排。比较每个单元的 ID 与内容 hash，而非只看 ID 集合。新评论出现时同时检查旧评论是否编辑；新一次部分采样未见旧评论，不推断它已删除。相同文本可复用载荷，但两个叙述者或来源出现位置仍单独保留。

同一 source_id 的两个正文版本不按“较长”“先出现”挑一个丢掉另一个；保存各版本定位和变化关系，再由现有契约选择当前版本。缺少稳定 ID、版本证据或依赖描述时，重读受影响 facet，必要时连同上下文一起重读。

复用命中、失效原因和待处理单元写入已有 review/run receipt；不新建独立缓存状态库。

### 4. 维度化上下文

按来源、正文、评论、转录、作者、剧集、引用等自然边界组织输入，保留跨 facet 依赖。局部内容可只传一次，关联的来源/角色/位置仍保留。索引不把“新颖”或“相关”作为机器筛除条件；现有业务要求的全读范围保持不变。

### 5. 保持原有分析能力

纯结构处理由代码完成，语义判断继续归 Agent。此次重复消除不包含默认换低能力模型、降低推理深度或减少审核要求；如要改变模型策略，另按原任务验收对照验证。模型失败、响应截断、分析覆盖不全时，保留待处理单元，不将请求成功等同于分析完成。

### 6. 对话上下文隔离

每轮使用短 evidence packet，实际送入模型的是投影而不是完整机器 manifest。相同内容只传一次，保留所有来源绑定；索引自身也按需分页或引用，不把几千个稳定 ID/hash 每次重新粘贴。综合读取有效分析和当前变化及其依赖；需要原文核验时仍可回到原始单元。

## 收益衡量

先在同一证据范围和分析目标下证明覆盖不退化，再比较总输入、输出、重试、重复加载与复用成本。以模型 usage 为实际计费事实，字节数、字符数、估算 token 分别标注。短包比全文小只证明载荷缩小；尚未执行的深读应计入剩余成本，不宣称已节省对应分析成本。共享 Skill 不承诺固定周预算或固定降幅，项目实测留在项目证据中。

## 伪优化

不以更小 limit、只抓前 N 条、只留高赞评论、关键词删除正文、摘要替代原文、平台总量替代实际样本或静默丢弃失败来换 token。

跨项目采用时，复用目标项目已有 `completeness`、Evidence、Runtime 和消费者；本参考不拥有业务数据、状态或调度器。

## 可复用的上下文包契约

目标项目已有短包组装器时，在已有契约中映射以下语义，而不是把 raw JSON 直接拼进模型请求。`agent-context-packet.v1` 是一种实现示例；字段可沿用本项目命名，不要求其他爬虫新建同名状态或周度目录。

```yaml
run_ref: <current-run>
analysis_scope_ref: <required-units-and-review-policy>
new_sources: []
changed_facets: []
failed_routes: []
review_refs: []
next_queries: []
sources:
  - source_id: ...
    facets:
      - facet_id: <project-facet>
        facet_hash: sha256:...
        item_count: 0
        changed: true
        raw_ref: ...
        dependency_refs: []
agent_input:
  coverage: []
  chunks: []
```

定位和验收约束：

- source、version、facet、unit 分层定位；重复载荷共享一个文本引用，但保留各次出现的位置、数量和角色。
- chunk 明确指向原始文件 hash、JSON pointer/文本字段、字符偏移与单位；对多个 JSON 对象拼接后的偏移须有原始坐标映射，单独一个文件路径加拼接偏移不算原文定位。
- 在已有 review receipt 中分别记录新完成、验证后复用、待分析和缺证据的单元。按单元集合核对覆盖；同样的总数不证明同样的内容覆盖。
- packet 与索引都可从原始资料和实际 review 重建；旧 packet 命中不自动生成新的人审准入，也不替其他项目的 Runtime 或 Registry 做决定。

## 验收场景

把下面的行为映射为目标项目的回归样例；这份清单本身不是通过证据。

| 场景 | 必须观察到的行为 |
|---|---|
| 首次处理、没有历史 review | 要求的全部单元进入正常分析；只生成索引仍为待处理 |
| 内容/任务/依赖相同且旧 review 有效完整 | 正文不重复传入，复用引用与实际覆盖可回放 |
| Hash 未变，但旧 review 丢失、截断或只审了部分 chunk | 仅复用有证据覆盖的部分，其余仍待分析 |
| 新增5条评论，同时1条旧评论被编辑 | 新增5条和编辑1条全部进入变化集合；其依赖结论重新核对 |
| 同 ID 两个版本，较短版本是新版本 | 保留版本关系，禁止按长度吞掉短版本 |
| 同文字来自两个作者/两个位置 | 可共享载荷，作者/位置/出现次数各自保留 |
| 当前采样未返回某条旧评论 | 标记本次未观察到；无结束证据时不推断删除 |
| 问题、规则、模型能力要求或父帖语境变化 | 旧 review 重新做适用性检查，受影响的综合结论失效 |
| JSON嵌套、转录时间戳、字符偏移或解析版本变化 | 逐条回放到正确原文位置；不明确时保留正常重读 |
| 缓存损坏、并发版本冲突、身份不明确 | 保留原始证据和待处理范围，沿原流程继续而非静默成功 |

验收分开说明：原始采集范围、原文可回放性、所需分析单元覆盖、有效复用与失效传播、实际端到端成本。仅包体变小、单测数量增加或索引构建成功不构成能力不退化的完整结论。
