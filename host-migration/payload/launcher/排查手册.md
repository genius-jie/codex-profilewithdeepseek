# Codex++ 排查手册

> 一页纸说清：入口怎么走、出问题跑哪条命令、哪些东西绝对不能碰。
> 契约细节看 `AGENTS.md`；本手册只管"怎么用、怎么修"。

## 入口地图（唯一的启动链）

```
桌面 "Codex++ 启动.lnk"
  └─ Start-CodexPlusPlus-Proxy.vbs        （隐藏启动零闪窗，失败才弹错误对话框）
       └─ pwsh7 Start-CodexPlusPlus.ps1 -SkipConnectorSync -SkipOpenCliAdapterSync -SkipSessionPathTest
```

`Start-CodexPlusPlus-Proxy.cmd` 是可见控制台的诊断入口（日志直接显示在窗口里），平时不双击它。

其他入口各司其职，**没有第二条启动路径**：

| 入口 | 干什么 |
|---|---|
| `codex-plusplus-codex` / `codex-plusplus` 命令 | CLI；`update`/`repair` 自动路由到受控入口 |
| 桌面 "Codex 隔离自检.lnk" | 验证原生/++ 没有互相污染 |
| `Repair-CodexPlusPlusCurrentApp.ps1` | 修 store（Sync 的薄代理） |
| `Sync-CodexPlusPlusLatest.ps1 -Once` | 一次性维护/镜像修复的唯一 owner |
| `Update-CodexPlusPlusInstaller.ps1` | 升级官方安装源（S34 流程） |
| `Protect-CodexPlusPlusGovernance.ps1` | 手动治理审计（只读） |
| `Sync-CodexPlusPlusConnectors.ps1` / `Sync-OpenCliAdapters.ps1` | 手动全量同步工具（启动链默认跳过） |

## 守卫三态（点快捷方式时发生什么）

1. **没在跑** → 正常全新启动。
2. **在跑且窗口能唤出**（含托盘隐藏）→ 唤出主窗口后直接退出，绝不碰现有实例。
3. **在跑但唤不出任何窗口**（窗口崩溃残留）→ 黄字提示"执行设计内清理并重启"，自动清理残留进程并全新启动。

`-Restart` 开关 = 强制走第 3 条路（整树清理 + 全新启动），覆盖"窗口唤得出但点不动"的渲染假死。

## 症状 → 一条命令

| 症状 | 处置 |
|---|---|
| 点快捷方式没反应 | 再点一次（三态守卫会自动处理）；仍不行看下一条 |
| 窗口出来了但点不动（假死） | `pwsh7 Start-CodexPlusPlus.ps1 -Restart` |
| 启动报错（有错误弹窗） | 直接跑 `Start-CodexPlusPlus-Proxy.cmd`，控制台窗口会显示日志 |
| 怀疑原生/++ 串配置 | 双击桌面 "Codex 隔离自检" |
| 会话列表标题乱码/路径带 `\\?\` | 手动跑一次会话维护：`pwsh7 Watch-CodexPlusPlusSessionPaths.ps1` |
| 超大会话卡渲染器 | 同上；冷存档在 `@@CODEXPP_HOME:win@@\quarantined_sessions\` |
| 旧项目会话仍显示但点击报 `no rollout found` | Codex++ 退出后运行 `python D:\CodexPlusPlusMigration-20260922\reconcile_codexpp_local_catalog.py`；它只把 D-only `codex-dev.db` 中不在 canonical `state_5.sqlite` 的 local 条目标记为缺失，再重启 Codex++ |
| 受控启动在 Windows 沙箱预检报 1223/UAC cancelled | 不复制其他 profile 的旧 `sandbox_users.json`；通过桌面入口重新运行一次，在唯一 UAC 提示中允许 setup，随后重跑 `Test-CodexPlusPlusSessionPaths.ps1` 和窗口运行时检查 |
| store 损坏/注入丢失 | `pwsh7 Repair-CodexPlusPlusCurrentApp.ps1`（需 ++ 已退出） |
| 升级官方新版本 | `codex-plusplus-codex update`（走 S34 受控流程） |
| 侧边栏“最近”转圈圈/卡无限滚动 | runtime 内置 fetch guard 自动返回空分页并优雅收敛；若异常则重新编译 runtime 并 `-Restart` |
| 最小化后点击桌面图标唤醒卡死/点不动 | 已建立内部 HTTP `/wake` 解除后台节流；若需强制唤醒可直接点击任务栏图标或重跑启动脚本 |
| 唤醒时误带出老宠物/Avatar辅助窗 | 启动器和 runtime 已加尺寸过滤器（>=500x400），仅唤醒主窗口 |
| 需要把原生登录态/CLI 适配器同步过来 | `Sync-CodexPlusPlusConnectors.ps1` / `Sync-OpenCliAdapters.ps1`（手动场景才用） |
| 开启新会话（无项目）报 `ENOENT: ... mkdir ...\Documents\Codex\...` | `config.toml` 中 `[desktop].projectlessWorkspaceRoot` 不是物理 D 根或误设为具体日期子目录；核对或切回 `@@CODEXPP_PROFILE:win@@\Documents\Codex` |

## 启动日志 8 个阶段（LOG 编号沿用历史，无 2/9）

| 阶段 | 内容 | 桌面入口是否执行 |

| 5/9 | 注入预检 + 修复决策（健康时不跑全量修复） | 执行 |
| 6/9 | loader 注入验证 | 执行 |

## 安全边界（杀进程/删文件前必看）

**绝对不动（原生 Codex，正在使用）：**
- `@@PROGRAMFILES:win@@\WindowsApps\OpenAI.Codex_*` 的进程与文件
- `@@USERPROFILE:win@@\AppData\Local\OpenAI\Codex`
- `@@CODEX_HOME:win@@` 与 `@@USERPROFILE:win@@\AppData\Roaming\Codex`

**Codex++ 专属（可动）：**
- 进程：可执行文件路径在 `@@CODEXPP_INSTALL_ROOT:win@@\store-apps\` 前缀下
- 配置：`@@CODEXPP_PROFILE:win@@`（物理目录；C 盘 Profile alias 已退役）
- 脚本：`@@LAUNCHER_ROOT:win@@\`

所有清理逻辑都按 store-apps 路径前缀过滤，脚本自带的杀进程函数不会碰原生实例；手动杀进程时也必须遵守同一前缀边界。
