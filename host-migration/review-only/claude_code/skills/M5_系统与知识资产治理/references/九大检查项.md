# M5 九大防偷懒检查项合规巡检（ALW-01~09）

> 由 M5 SKILL.md 外置。完整检查项表与整改强制力见正文。

### [STATE: ANTI_LAZINESS_COMPLIANCE_AUDIT] (九大检查项合规巡检)
> 本状态门对应 `execution.md §7.1` 中定义的九大防偷懒检查项通用基座。M5 在巡检时必须逐条核验这些检查项在 W1、P 系、S 系各层的物理落实情况。

**巡检触发条件**：每次 M5 被唤醒执行全域治理扫描时，本状态门必须被穿透，不可跳过。

**九条审计检查项**（每条对应一个检查项）：

| 检查项 ID | 审计目标 | 合格标准 | 违规判定 |
|:--|:--|:--|:--|
| `ALW-01` | **MapReduce 分片** | W1 的 `dry_run_spec` 和 P3 的执行日志中存在 Slice 切分记录，且每 Slice ≤ 声明的 `max_slice_lines` | 发现单次吞入超过阈值的文件、或缺乏 Slice 切分记录 → `VIOLATION` |
| `ALW-02` | **状态外挂** | 长任务（跨会话或 Slice > 5）的 `progress/` 目录下存在对应的 `.json` 状态文件，且 `lastUpdated` 在执行窗口内 | 长任务无外挂状态文件、或 `lastUpdated` 早于执行开始时间 → `VIOLATION` |
| `ALW-03` | **人机审批门禁** | 未发现执行者在未经审批的情况下扩大任务范围 | 发现执行产出涉及 `scope` 外文件且无 `SCOPE_EXTENSION_REQUEST` 记录 → `VIOLATION` |
| `ALW-04` | **金丝雀陷阱** | Dry-Run 报告中 `canary_hit` 字段为 `true` | `canary_hit` 为 `false` 或字段缺失 → `CANARY_MISS`（报告作废） |
| `ALW-05` | **物理证据指针** | 产出中每条 finding/判断都携带 `evidence_pointer`，且指向真实存在的文件和行号 | 发现无 `evidence_pointer` 的结论、或指针指向不存在的文件 → `VIOLATION` |
| `ALW-06` | **最低覆盖配额** | `completedSlices / totalSlices >= min_coverage_quota`（默认 100%） | 覆盖率不达标且未标注 `[blocked]` 原因 → `INCOMPLETE` |
| `ALW-07` | **回读验证** | 存在回读验证记录（抽检了哪些 Slice、验证结果如何） | 缺乏回读验证记录、或抽检比例 < 30% → `VIOLATION` |
| `ALW-08` | **输出模式强制** | 产出遵循声明的结构化模板（JSON 对象/表格），无大段散文替代 | 发现用散文段落替代应有结构化字段 → `FORMAT_VIOLATION` |
| `ALW-09` | **双路径交叉** | `depth=full` 的审计存在 M12+M9 双视角交叉比对记录 | `depth=full` 但仅单视角产出且未标注盲区 → `SINGLE_VIEW_RISK` |

**审计执行方式**：
- M5 对最近 N 次（默认 N=3）的 W1 契约、P 系交付物、S 系回执进行抽样扫描
- 对每个样本逐条跑以上 9 个检查项，产出 `anti_laziness_audit_result[]` 数组
- 违规项计入 M5 的 JSON 报告的 `cognitive_diagnosis` 段

**整改强制力**：
- `VIOLATION` 级别：标记为 `BLOCKER`，该产出链上的所有下游交付物冻结，直到违规方补齐证据
- `CANARY_MISS` 级别：整份报告/交付物作废，触发重做
- `FORMAT_VIOLATION` / `SINGLE_VIEW_RISK` 级别：标记为 `WARNING`，不阻断但写入经验队列 `experience_queue.md`
