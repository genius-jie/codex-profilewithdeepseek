# 错题本：M5_系统与知识资产治理

> **警示总结与实战经验记录**：
> 凡是在执行 M5 的双维合并与自动检查过程里采过的雷，必须在此强制登记。以防未来在探针雷达或者最高法理审判时因为相同的机制重蹈覆辙。

## M5 历史阵亡点（排雷日志）

### 关于父子指针断链与 Linter 的缝合故障
由于某些模块因为使用手动拷贝，未及时同步更正 `extends` 头部的指向；Linter 在强约束审计过程中发现该缺陷，必须借助 `os_parent_child_syncer.ps1` 执行自愈操作。如果 Linter 报错但 Syncer 无法救场，多半是因为目标的本质是一个非法侵入的 `Symlink` 伪类，须利用 M5 特权法则直接将其打回软链原型去。

### "执行探针与脑力裁断分离"之伤
早年 M5（探针）与原来的 M6（思考脑）分离时，极易导致架构状态机断层（探针查出问题之后要扔回工作流调度，工作流再去请示 M6）。M5 吸收两者合为一尊后，"看到垃圾立刻就地重构治愈"才是正确的高效运转模式！严禁再次拆开这两部分流水操作。

### docs/ 资产治理必须走 S27 逐一深度审计，严禁仓促批量删除 (2026-04-02)
- **🎬 场景**：在进行全域知识图谱测绘后，发现 `docs/` 下有 3 份散落文件不符合数字容器法则。Agent 错误地一次性 `Remove-Item` 批量铲除了全部文件，包括极具历史价值的铁律创世纪文档。
- **🔍 根因**：Agent 把"不符合存放规则"等同于"可以直接删除"，跳过了 S27 分批阅读法的逐一评估流程。M5 的职责是"治理整改"，不是"无脑粉碎"。
- **💊 解法**：所有资产整改必须走完整的 **11 维审计框架**（详见 `references/methodology/09_Asset-Governance-Audit-Protocol.md`），每份文件单独出具评估报告并经用户确认后才能执行处置。
- **💡 经验**：发现违规 ≠ 立即删除。M5 做的是"治理"不是"无差别删除"。

### docs/ 文件命名禁止以日期为前缀 (2026-04-02)
- **🎬 场景**：历史文件 `2026-03-20_提示词架构升级总结.md` 以日期打头。
- **🔍 根因**：日期是元数据而非身份标识。以日期开头会导致按名排序时丧失主题聚类能力，"命名即语义"的设计哲学彻底失效。
- **💊 解法**：日期退到 YAML frontmatter 的 `created` 字段中。文件名只保留主题关键词。
- **💡 经验**：文件名的黄金位置留给"这是什么"，而不是"什么时候写的"。

### docs/ 五大强制数字容器必须物理落地 (2026-04-02)
- **🎬 场景**：`README.md` 明确写了 `docs/` 下有 5 个强制数字容器（01-05），但实际上从未创建过这些目录。
- **🔍 根因**：规则写了但没有物理执行，属于"有法不依"的架构空白。
- **💊 解法**：M5 巡检时，如果发现规则定义的物理结构不存在，必须主动创建并将现有文件归位整理。
- **💡 经验**：规则不落地等于没有规则。

## [2026-04-10] GraphFlow 自愈容错需要架构定级方法论配合
- **症状**：GraphFlow 自愈容错重构时，发现多 Agent 路由需要从大模型盲扫改为有向图约束，但定级标准不清晰。
- **病因**：M5 系统资产治理层面缺乏对多 Agent 拓扑组件的架构定级方法论，导致重构时缺乏判别依据。
- **解法**：将多 Agent 拓扑编排纳入 M5 架构定级体系，明确何时用 GraphFlow（固定流水线）、何时用 Swarm（动态协作）、何时用 SelectorGroupChat（多视角审核）。

### 文件重命名后必须执行全域正文 grep 扫描，不能只修 YAML 头 (2026-04-23)
- **🎬 场景**：对 `references/methodology/` 下的文件做批量重命名+合并（如 `w1-weapons-registry.md` → `21_W1-Weapons-Master-Registry.md`，AutoGen 管线白皮书旧编号 → `18_AutoGen-Pipeline-Governance.md`），仅修复了各文件 YAML 头的 `related` / `extends` 引用，宣布完工。
- **🔍 根因**：YAML 头部是结构化元数据、好 grep、好改。但大量引用散落在 SKILL.md 的正文表格、武器来源注释、副脑掩体列表等**非结构化正文**中。上轮操作者产生了"改完 YAML 头就等于改完全部"的认知盲区，导致 23 条断链在正文中潜伏。
- **💊 解法**：凡是涉及 methodology / references 文件重命名，**必须同时执行两轮 grep**：(1) `grep_search` 搜 YAML `related`/`extends` 头部引用；(2) `grep_search` 搜正文中的相对路径和短文件名引用（表格、注释、backtick 代码块内）。两轮都清零才算完成。
- **💡 经验**：YAML 头是门面，正文是内脏。只修门面不修内脏 = 定时炸弹。建议后续封装 `link-integrity-checker.py` 脚本做自动化回归。
