## 域专属错题本

### 2026-06-23｜定时任务无上下文导致日报质量崩塌（标本兼治修复）

**问题**：龙虾定时任务（每晚八点）自动调用 S19 生成日报时，由于**无对话上下文**，导致日报质量严重下降：
- 内容又短又看不懂，领导不懂技术完全看不懂
- 技术黑话堆砌（如"异步自旋断言"、"时序边界编排"）
- 项目归属混乱，范围不完整（只聚焦单个项目，遗漏跨域工作）
- 待办事项缺失或敷衍

**根因分析（第一性原理）**：
1. **证据链断裂**：定时任务在"零会话状态"下运行，无法获取当天工作任务语义，只能拿到文件变更的物理事实
2. **项目归属判定失效**：`collect_daily_changes.py` 只能做物理路径归集，业务大项目归类必须交给 Agent 结合三入口输入流判断
3. **定时任务产物混入**：自动生成的日志、状态文件被误认为是"今日工作成果"
4. **缺乏防御机制**：S19 没有"无上下文拒绝生成"的防御能力，被迫用碎片文件硬凑日报

**修复方案（标本兼治）**：

**治标（立即生效）**：
1. **新增 [STATE: CONTEXT_VALIDATION] 前置关卡**：S19 必须在生成日报前验证上下文存在性
2. **新增 [STATE: DEGRADED_DRAFT] 降级模式**：无上下文时强制输出"草稿（待确认）"，明确标注"缺乏工作上下文，请人工确认"
3. **重构 collect_daily_changes.py**：
   - 移除代码层业务项目归属推断，只输出物理工作区事实，业务归类由 Agent 在日报编写阶段完成
   - 增加 `AUTO_TASK_PATHS` 定时任务产物过滤，自动排除日志、缓存等噪声
   - 输出按项目聚合的摘要，而非零散文件列表

**治本（架构级修复）**：
1. **建立 S19-Cron-Context-Contract.md 契约**：规定定时任务调用 S19 时必须传递 `daily-context.json`，包含当天工作会话摘要、完成任务列表、待办事项
2. **违约处理机制**：如果定时任务未提供上下文，S19 有权拒绝生成正式日报，仅输出降级草稿
3. **契约条款**：
   - 条款 1: 上下文文件强制传递（`daily-context.json`）
   - 条款 2: 无上下文防御（拒绝生成正式日报）
   - 条款 3: 上下文验证（必填字段、日期匹配检查）
   - 条款 4: 龙虾定时任务改造（按契约生成上下文文件）

**验证标准**：
- 无上下文时，S19 必须输出降级草稿，不得伪装成正式日报
- 定时任务产物必须被过滤，不得进入日报正文
- 文件变更必须按业务大项目聚合（Codex 基础建设、PatchX 智测平台等）
- 日报必须包含：工作内容（口语化）、项目归属、待办事项

### 2026-05-07｜脏工作树不能直接写成日报成果

**问题**：生成日报时，把其他仓库的 `git status -s` 游离改动直接写成"今日完成项目"，误报了 PatchX 智测平台和 AI 测试用例中台。

**根因**：S19 的物理取证分了层，`git status` 只能证明"有未提交改动"，不能证明"今天确实做了这个任务"。把风险线索当成交付成果，就是日报事实边界混乱。

**正确做法**：日报成果必须同时命中当天对话语义、今日提交、pipeline_state 证据或明确执行记录。只有脏文件、没有当天任务语义时，最多写进"待收口风险"，不能写成完成项。
