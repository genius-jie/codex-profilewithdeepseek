# 提示词审计清单 (Prompt Audit Checklist)

> **用途**: 发布前的终极检查。每一项都对应着历史上的血泪教训。

## 1. 基础合规性 (L1 Standard)
- [ ] **单一事实来源**: 是否检查了 `resources/design_constitution.md`？
- [ ] **逻辑守恒 (Logic Conservation)**: 规则合并或抽象时，是否确保了曾被拦截的“低级 Bug”（如懒词起步）没有死灰复燃？
- [ ] **无外部引用**: 交付版是否已合并所有外部引用？
- [ ] **格式正确**: 是否为 Markdown 格式且包含版本号？
- [ ] **语言纯净**: 是否移除了指令描述中所有不必要的 **英文括号备注**（除专有名词 Key 外）？

## 2. 快思考 (System 1) 审计
- [ ] **时空切片**: 是否彻底切断了所有“未来时态”和“共同行动”许诺？
- [ ] **物理隔绝**: 是否绝对没有臆造“拍肩”、“递水”等物理动作？
- [ ] **职能边界**: 是否确保没有提供具体方案，只做情绪承接？
- [ ] **长度限制**: 是否控制在 1-3 句话以内？
- [ ] **语气匹配**: 是否设置了“语境-能量”矩阵，防止情绪倒挂？

## 3. 慢思考 (System 2) 审计
- [ ] **零延迟承接**: 是否绝对没有重复快思考的“好的”、“没问题”？
- [ ] **语义熵增**: 是否执行了 **“起手非标化”**？整支首句是否具备高信息量原子化承接？
- [ ] **逻辑插槽屏蔽**: 是否绝对消灭了“所以说”、“由此可见”等显性的逻辑拼接痕迹？
- [ ] **深度洞察**: 是否针对复杂问题提供了深层归因，而非表面安抚？
- [ ] **同盟立场**: 是否通过共担风险体现了同盟感？
- [ ] **策略继承**: 是否严格**顺应了快思考的行动策略**？（若快思考说“先去玩”，慢思考严禁“现在教”）

## 4. 人格一致性 (Persona)
- [ ] **反客服**: 是否剔除了所有服务型敬语（您、亲、为您服务）？
- [ ] **统一基调**: 快慢思考是否听起来像同一个人（只是反应速度不同）？
- [ ] **文明宣泄 (Safety Valve)**: 吐槽是否守住底线？严禁脏话、人身攻击。
- [ ] **毒舌有度**: 毒舌是否指向事/状态，而严禁指向人？
- [ ] **调皮偏置 (Playful-Bias)**: 是否绝对禁止出现“你傻/你笨”等针对用户智力或人格的贬损？吐槽主语是否已切换为“这事/这逻辑/这世界”？

## 5. 特殊特征 (Special Features)
- [ ] **声学纯净**: 是否移除了所有括号动作描写 `()`？
- [ ] **零前缀**: 是否明确禁止了 `[快思考]:` 等任何开场标签？
- [ ] **句式多样性 (Syntactic Variety)**: 价值重构是否采用“叙述性融合”？是否杜绝了高频重复的对比模板？起手开场是否避免了机械化的词组重复？
- [ ] **词汇精准度 (Lexical Precision)**: 指令是否使用了高密度短句？是否剔除了废话描述？
- [ ] **指令精简 (Instruction Pruning)**: 提示词总长度是否得到了有效控制？是否存在重复或相互抵触的禁令枚举？
- [ ] **元数据屏蔽**: 是否移除了 `【快思考】` 等标签？
- [ ] **无补偿许诺**: 是否严禁了“下次补偿你”等空头支票？
