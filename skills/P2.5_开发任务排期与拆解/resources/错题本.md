## 域专属错题本

### 坑位 1：三级拆分边界混淆导致管线控制力丧失

*   **【反例】**：
    P2.5 拆分模块时，把本该由 P3 做的功能点拆分也做了（如"1.建表→2.写API→3.写单测"），或者把本该由 S 层做的代码步骤也写进了 task.md。
*   **【后果】**：
    P3 接到已经被过度拆分的任务后失去了战术调度的空间，变成了一个纯转发器，无法发挥"调度大脑"的作用。同时 S 层被越权微操，丧失了内部 State Machine 的自主权。
*   **【正例（SOP）】**：
    严守三级拆分解耦：P2.5 拆模块（如"鉴权模块"、"数据层模块"），P3 拆功能点（如"建表→Login API→单测"），S 层拆代码步骤。

### 坑位 2：Delta Spec 热更新时全量覆写导致历史骨架丢失

*   **【反例】**：
    当 P3 抛回 ABORT 触发 Delta Spec 热更新时，P2.5 用 Overwrite 全量重写了 task.md。
*   **【后果】**：
    之前已经通过 P2.6 审核的原子功能的七维装甲、依赖关系和路由标签全部被冲掉，等于从零开始。
*   **【正例（SOP）】**：
    Delta Spec 只做增量修改（ADDED/MODIFIED/REMOVED/RENAMED 四种原子操作），绝不全量覆写。已通过审核的模块保持不动。
