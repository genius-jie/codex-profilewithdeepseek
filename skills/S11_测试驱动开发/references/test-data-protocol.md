# 测试数据设计规范（全生命周期）

> **核心原则**: 正交性, 覆盖率, 边界感, 真实性

---

## 一、需求分析阶段

> 拿到测试数据任务时怎么拆解需求

### 1.1 常见陷阱：测试维度单一

- **根因**: 仅根据"功能点"设计正常场景，忽略了恶意攻击和异常输入。
- **对策**: 强制使用 **"5+X" 分析法**（正、反、边缘、异常、极限 + AI特色维度）。

### 1.2 常见陷阱：数据不可追溯

- **根因**: CSV 中没有锚定 Test Point ID，导致 A6 报告无法自动计算覆盖率。
- **对策**: 所有构造的执行数据文件**必须显式包含** `test_point_id`。

### 1.3 常见陷阱：环境配置硬编码

- **根因**: 在 JMX 或数据文件中硬编码特定环境的 IP/Port。
- **对策**: 环境配置必须抽离为 config.properties 或外部传递的 `-J` 参数。

### 1.4 常见陷阱：沉迷理想路径测试 (缺陷驱动与防呆原则)

- **根因**: 测试设计只走理想流 (Happy Path) 导致健壮性测试缺失。
- **对策**: 专门针对历史易错点，主动注入网络延迟、非法 JSON、超长边际值和鉴权丢失等刺探数据，以"找茬"的心态验证健壮性。

## 二、设计阶段

> 测试数据的设计原则和方法

### 2.1 多维测试用例设计规范

#### 基础维度 (The Essentials)
- **正面用例 (Happy Path)**: 验证功能按预期工作。
- **反面用例 (Negative Cases)**: 验证系统在错误输入下的容错能力。
- **边界值 (Boundary Value)**: 验证临界点的处理（如最大长度、最小数值）。
- **等价类 (Equivalence Class)**: 减少重复劳动，选择代表性数据。

#### 健壮性维度 (Robustness)
- **异常格式**: 传入错误的 JSON 结构、非法字符集、超长 Payload。
- **类型不匹配**: 数值字段传入字符串，布尔值传入 null。
- **并发冲突**: 模拟多条相同数据的瞬间写入或分布式争抢。

#### AI 特色维度 🤖
- **不合规诱导**: 引导 AI 产生色情、暴力或政治敏感内容。
- **提示词注入 (Prompt Injection)**: 尝试绕过 System Prompt 约束。
- **幻觉/稳定性**: 验证相同输入下核心输出的一致性。

### 2.2 数据契约设计规范 (Data Contract Standards)

> **来源**：萃取自数据契约规范

#### 契约四要素（必备）

| 要素 | 内容 | 必须 |
|:----|:-----|:----:|
| **字段定义 (Schema)** | 名称、类型、必填、取值规则、默认值、依赖关系 | ✅ |
| **业务规则** | 枚举映射、字段间逻辑约束、场景分类 | ✅ |
| **数据场景覆盖** | 全量场景定义（含边界值、异常值、特殊字符） | ✅ |
| **执行闭环参考** | DDT 映射规则、JMX 变量映射、断言设计指导 | ✅ |

#### 契约是唯一事实来源

- 所有测试数据（CSV）**必须**依据数据契约生成，禁止脱离契约自行发明字段
- 下游 Skill 遇到与契约不一致的数据，**必须快速失败**
- 契约变更**必须**走版本化管理

#### 跨阶段数据一致性检查

- DDT 生成后，**必须**校验字段值是否满足契约约束
- 断言设计**必须**覆盖核心字段
- 数据调整**必须**同步更新契约文档

#### 契约文档标准结构

```markdown
# [项目名称] 数据契约文档
## 1. 字段定义
## 2. 业务规则（字段依赖 + 枚举映射 + 场景分类）
## 3. 数据场景覆盖（正常/异常/边界/性能）
## 4. DDT 映射规则
## 5. JMX 脚本参考
## 6. 断言配置参考
## 7. 数据一致性与调整
```

## 五、知识回流阶段

> 测试数据领域的经验沉淀

### 5.1 5+X 高维组合数据剧本设计法

- **根因**: 系统往往对单一"恶意 Prompt"防御极好，但在组合了"真实参数"与"隐蔽数值越界"的复杂剧本下会暴露后门。
- **对策**: 测试数据生成必须采用**多维度正交/笛卡尔积剧本**：
  - 『完美的语义请求』 + 『单一边界参数突变』
  - 『恶意的 Prompt 注入』 + 『合法的地理坐标』
- **价值**: 此法曾在 500 并发压测中成功探测出高危的"超量数据泄露" BUG。
