# 模型切换与换机自检

> 用途：新增 provider、换机接手、目录同步之后，以及"切到某个模型就报错"时，按本清单走一遍。
> 判据全部来自实测，不是推断；本机实测时间 2026-11-06，链路 = Codex++ → 15740 适配器 → 48760 CodexManager → RunningHub 聚合。

## 1. 三条不变量（先背）

1. **一把钥匙**：48760 只认 `api_keys` 表里注册的那一把（`gk_` 前缀 id + 64 位 Hex 密钥）。`config.toml` 里任何 provider 的 `experimental_bearer_token` 必须是这把密钥的真身，不能是 `sk-` 链接 token、不能是 `gk_` 的 id 本身。
2. **一个 provider**：`model_provider = "cm_aggregate"`（指向 15740）。Claude 的输出预算注入、Messages 翻译、grok 的 reasoning 参数降级全都在 15740 里；切到 `cm`（直连 48760）会同时丢掉这三样。
3. **压缩阈值必须小于上下文窗口**：`auto_compact_token_limit < context_window`，否则永远不触发压缩，长会话直接撞墙。

## 2. 五步自检

| 步 | 动作 | 通过判据 |
|---|---|---|
| 1 | 读 `config.toml` 的 `model_provider` 与其 `base_url` | 指向 `http://127.0.0.1:15740/v1`，不是 48760 |
| 2 | 比对密钥：`[model_providers.cm_aggregate].experimental_bearer_token` 与 `[model_providers.cm]` / `auth.json` 的 `OPENAI_API_KEY` | 两者一致且为 64 位 Hex |
| 3 | 跑 `python probe-model-matrix.py` | 目录里所有要用的模型返回 `ok` |
| 4 | 看 48760 `request_logs` | 每条都是 `sc=200 key=gk_xxx`；出现 `model=None key=None sc=403` 就是鉴权前置拒绝 |
| 5 | 看 15740 日志 | Claude 侧有 `adapting responses -> anthropic messages` + `injected output token budget`；缓存命中率长期 >0 |

401/403 出现时的正确读法：`model=None` + `key=None` 说明鉴权中间件在解析 body 之前就拒绝了，**不要怀疑模型名**，直接查第 2 步的钥匙。

## 3. 实测矩阵（2026-11-06，42 个目录模型）

口径：15740 + 真钥匙 + 各模型支持的最高思考档 + 非流式；关键模型另做 SSE 流式复测。

| 类别 | 数量 | 模型 | 结论 |
|---|---|---|---|
| 直接可用 | 30 | claude 全家、`grok-4.7`、`xai/grok-4.7`、`xai/grok-4.6`、`gpt-6.1-sol`、`gpt-6-sol/luna`、`gpt-5.6-*`、`glm-5`/`glm-5.3`、`kimi-k3`、`kimi-k2.7-code`、`qwen3.8-*`(0902/flash)、`deepseek-v4-pro`/`v4-flash`、`gemini-4-argon` 等 | 切过去就能用 |
| 裸名无路由，改写法可用 | 4 | `gpt-6-astra`、`qwen3.8-max`、`deepseek-v4.1-flash`、`glm-5.2` | 换前缀：`openai/gpt-6-astra`、`qwen/qwen3.8-max`（或 `qwen3.8-max-0902`）、`deepseek/deepseek-v4.1-flash`（或 `-1017`）、`glm/glm-5.2` |
| 有路由但思考档受限 | 3 | `gpt-5.5`、`gpt-5.4`、`gpt-5.4-mini` | 裸名 404；`openai/` 前缀 + `max` 思考 → 502 `The request parameters are not supported by this model`；**只能 high** |
| 上游没有 | 4 | `gpt-5.2`、`gpt-5.5-openai-compact`、`gpt-5.3-codex-spark`、`gpt-reserve` | 加 `openai/` 前缀仍 404，选必挂 |
| 抖动 | 1 | `glm/glm-5.3-flash` | 三次两次 504 `Upstream first_byte timeout`，重试可能过 |

**方向性结论**：`model_not_found` / `model_unavailable` 属于上游没有该模型，与钥匙、适配器、provider 无关，改这三样都救不回来。

## 4. 两个只在"切换动作"上才会踩的坑

1. **切 provider**：`xai/grok-4.7` + `max` 思考直连 48760 会 502（reasoning 参数降级只在 15740 做）；Claude 直连还会复发 1024 输出上限。模型随便切，provider 别切。
2. **压缩阈值反转**：`kimi-k3`、`qwen3.8-max` 的 `auto_compact_token_limit=900000` > `context_window=872000`，等于永不自动压缩。这两个值被生成脚本 `host-migration/payload/launcher/Sync-CodexPlusPlusModelCatalog.ps1` 写死，只改 `model_catalog.json` 会在下次同步时被覆盖回去——**目录和生成脚本必须一起改**。

## 5. 换机执行顺序

1. 先确认实际 profile 位置：`config.toml` 所在目录就是 CODEX_HOME，不要按旧文档的固定盘符假设。
2. 取真钥匙：`[model_providers.cm].experimental_bearer_token` 或同 home 的 `auth.json.OPENAI_API_KEY`；两处应一致。只做存在性与长度核对，不打印原文。
3. 把真钥匙写进 `[model_providers.cm_aggregate].experimental_bearer_token`（改前备份 `config.toml.bak-<时间戳>`）。
4. 确认 `model_provider = "cm_aggregate"`。
5. 跑 `python probe-model-matrix.py`；对失败项按第 3 节表格判断是"改写法"还是"该删"。
6. 重启 Codex++（provider/目录都是 app-server 启动时读的），新开会话再用第 2 节第 4、5 步复核。

## 6. 维护契约

- 本文件里的模型清单会随上游上下架过期；**结论按类别复用，名单按当次实测刷新**，每次刷新把日期写进标题。
- 新增目录条目后，必须补跑一次矩阵；不允许"加进目录就算支持"。
- 生成脚本与目录文件是同一份事实的两处投影，改一处必须同步另一处。
